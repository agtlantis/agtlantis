# F9-T9.2 Finding — Anthropic Extended Thinking ↔ AI SDK `reasoning-*` Normalization

> Status: PoC complete (3/3 PASS), live API verified.
> Date: 2026-05-12
> Model: `claude-sonnet-4-6` via `@ai-sdk/anthropic@3.0.62` on `ai@6.0.39`
> PoC: [`reasoning.poc.test.ts`](./reasoning.poc.test.ts)

---

## 1. Question

Does Anthropic Claude extended thinking surface as `reasoning-*` chunks in AI SDK
`streamText`'s `fullStream`, the same way OpenAI and Google reasoning models do? Does
agtlantis need to extend its abstractions (e.g. a new resolver, a new chunk handler,
a new usage extractor) to absorb this?

## 2. TL;DR

| Axis | Result |
|------|--------|
| **Event normalization** | YES, full match. AI SDK emits `reasoning-start` / `reasoning-delta` / `reasoning-end` for thinking blocks — same shape as OpenAI/Google. |
| **agtlantis core interface impact** | NONE for `streamText` plumbing. `SimpleSession.streamText` returns AI SDK result as-is (`src/session/simple-session.ts:240-280`); consumer-side reasoning handling already works. |
| **agtlantis usage-extractors impact** | **YES — silent under-count**. AI SDK does NOT populate `usage.outputTokenDetails.reasoningTokens` for Anthropic thinking (it stays `{}`). The thinking tokens are bundled into `usage.outputTokens` total but invisible to the `reasoningTokens` accumulator in `src/session/usage-extractors.ts:30`. |
| **Provider options shape** | Sonnet 4.6 supports both `thinking: { type: 'enabled', budgetTokens }` and `thinking: { type: 'adaptive' }` discriminated-union forms. `sendReasoning: true` controls **multi-turn carry-forward of prior reasoning blocks** (whether the model receives its own past thinking on subsequent calls — gate in `@ai-sdk/anthropic@3.0.62 dist/index.js:2304-2305`). It does NOT gate streaming of reasoning chunks on the current call — that is determined solely by the `thinking` field. See §5 for the consumer-side resolver template. |
| **GO/NO-GO contribution** | **GO**. No agtlantis core surgery needed for reasoning streaming. One small follow-up: usage extractor tweak when the formal Anthropic provider lands. |

## 3. Empirical Event Sequence

### Scenario 1 — `thinking: { type: 'enabled', budgetTokens: 1024 }`

```
idx | type             | id | notes
----+------------------+----+--------------------------------------------------
 0  | start            |    |
 1  | start-step       |    | { request, warnings }
 2  | reasoning-start  | 0  |
 3  | reasoning-delta  | 0  | text="Time"
 4  | reasoning-delta  | 0  | text=" = Distance / Relative Speed = 100 / (60 + 40) = 100 / 100 = 1 hour."
 5  | reasoning-delta  | 0  | text="" + providerMetadata.anthropic.signature="EoUC..."
 6  | reasoning-end    | 0  |
 7  | text-start       | 1  |
 8  | text-delta       | 1  | text="The"
 9  | text-delta       | 1  | text=" two trains meet **1 hour** after departure, ..."
10  | text-delta       | 1  | text=" km/h covers the 100 km gap in exactly 1 hour."
11  | text-end         | 1  |
12  | finish-step      |    | providerMetadata.anthropic.usage.output_tokens=81
13  | finish           |    |
```

Counts: `reasoning-start: 1, reasoning-delta: 3, reasoning-end: 1, text-delta: 3`.

Concatenated reasoning text (72 chars):
> "Time = Distance / Relative Speed = 100 / (60 + 40) = 100 / 100 = 1 hour."

`signature_delta` from the wire is bundled into a `reasoning-delta` event with
`text=""` and `providerMetadata.anthropic.signature` — confirmed against compiled

### Scenario 3 — `thinking: { type: 'adaptive' }`

Counts: `reasoning-start: 1, reasoning-delta: 4, reasoning-end: 1, text-delta: 3`.

> 100 km/h. Distance is 100 km. Time = 100/100 = 1 hour."

Same chunk grammar as Scenario 1 — adaptive form does not change the
normalization. Adaptive uses higher output budget freely (`output_tokens=103`

depth on Opus 4.6+/Sonnet 4.6+.

## 4. Usage Accounting Gap (the only real finding)

Across all 3 scenarios, `usage.outputTokenDetails` was an empty object `{}`:

```jsonc
// Scenario 1 (thinking enabled, 1024 budget):
{
  "inputTokens": 84,
  "outputTokens": 81,
  "outputTokenDetails": {},   // ← reasoningTokens NOT separated
  "totalTokens": 165,
  "raw": { "output_tokens": 81, ... }
}
```

Implications for agtlantis:

- `src/session/usage-extractors.ts:30` accumulates
  `reasoningTokens += usage.outputTokenDetails?.reasoningTokens ?? 0`. For
  Anthropic calls this branch always reads `0` while `outputTokens` already
  includes the thinking tokens. **Net effect: silent under-attribution of
  reasoning tokens, but total accounting stays correct.**
- Cost calculation in `pricing/calculator.ts` (not directly read here, but per
  T9.1 archive context) bills against total `outputTokens` regardless, so
  monetary impact is zero. The discrepancy is purely an analytics one.
- The raw breakdown is available in `providerMetadata.anthropic.usage` on the
  `finish-step` chunk (`output_tokens: 81`), but Anthropic's response does not
  split `thinking_tokens` vs `text_tokens` at the API level today either — so
  even a richer extractor would need to derive thinking-token count by summing
  the `reasoning-delta` chunk lengths or trusting model budget hints.

### Recommended remediation

When the formal Anthropic provider lands (post-Spike, separate Feature):

1. **Provider-side extractor**: in the future `createAnthropicProvider`'s session
   wrapper, post-process AI SDK chunks and tally `reasoning-delta` text length
   → token estimate (or, if Anthropic adds a split field, read it). Surface it
   back through `usage.outputTokenDetails.reasoningTokens` at session merge
   time.
2. **No core interface change** for `mergeUsages` — it already keys on
   `outputTokenDetails.reasoningTokens`. The provider just needs to fill it.
3. **Documentation note** in `usage-extractors.ts` (or the new
   `provider/anthropic/` doc) that until #1 is implemented, Anthropic
   reasoning tokens are folded into `outputTokens`.

This is a P1 nit, not a Spike blocker.

## 5. `resolveReasoningOptions()` — Scope Clarification

The task brief mentioned `resolveReasoningOptions()`. Grep across
`packages/core/src/` returned no such symbol. F8 archive
(`refs/archive/F8-openai-migration.md:107, 283-290`) shows it was a layer in
the **consumer application** (`report-workspace-assistant`), not in agtlantis
core. agtlantis itself does not own a reasoning options resolver — it passes
`providerOptions` through verbatim
(`src/session/simple-session.ts:223-247`).

So the "extension" question reduces to **how the consumer's resolver should
shape `providerOptions.anthropic` to enable thinking**. Recommended template
for the consumer-side resolver:

```typescript
// In the consumer's resolveReasoningOptions (existing OpenAI pattern):
//   openai: { reasoningEffort: 'high', reasoningSummary: 'detailed' }
// New Anthropic branch:
function resolveAnthropicReasoning(level: ReasoningLevel | undefined):
  AnthropicLanguageModelOptions | undefined {
  if (!level || level === 'off') return undefined;
  return {
    // Use adaptive form on Sonnet 4.6+/Opus 4.6+; budgetTokens form on earlier.
    thinking: { type: 'adaptive' },
    effort: level === 'high' ? 'high' : level === 'medium' ? 'medium' : 'low',
    sendReasoning: true, // surface thinking in stream + carry forward in multi-turn
  };
}
```

Notes:

- `effort: 'low' | 'medium' | 'high' | 'max'` works only with `thinking.type:
  'adaptive'` (Sonnet 4.6+/Opus 4.6+). For older models, use `{ type: 'enabled',
  budgetTokens }` instead.
- `sendReasoning: true` is the analog of OpenAI's `reasoningSummary: 'detailed'`:
  it controls whether reasoning blocks ride along to the model on subsequent
  turns. Required for multi-turn agents that need the model to see its own prior
  thinking.

These are **consumer concerns**. agtlantis core remains untouched.

## 6. AI SDK Confirmation (source-level)

For traceability, the chunk-type names come directly from compiled
`@ai-sdk/anthropic@3.0.62`:

```
dist/index.js:3802-3808   thinking → reasoning-start
dist/index.js:4216-4222   thinking_delta → reasoning-delta { text }
dist/index.js:4224-4237   signature_delta → reasoning-delta { text:'', providerMetadata.anthropic.signature }
dist/index.js:4152-4156   content_block_stop on thinking → reasoning-end
```

> Internal-vs-public key note: The compiled SDK calls
> `controller.enqueue({ ..., delta: ... })` at lines 4216-4222 / 4224-4237, but
> the fullStream chunk that consumers iterate on exposes the same incremental
> payload under the **`text`** field (AI SDK v6 v5-stream public shape — empirically
> verified in PoC, see Scenario 1 events idx 3-5). Tooling that filters chunks
> should read `chunk.text`, not `chunk.delta`. The PoC `recordChunk()` helper
> captures both fields defensively as a forward-compat safeguard.

`AnthropicLanguageModelOptions` type
(`dist/index.d.ts:132-218`) confirms:

- `thinking: discriminated-union { adaptive | enabled+budgetTokens | disabled }`
- `effort: 'low' | 'medium' | 'high' | 'max'`
- `sendReasoning: boolean`

## 7. Decision

**Reasoning normalization: GO with zero agtlantis core change.**

- AI SDK already normalizes Claude thinking blocks to `reasoning-*` chunks
  matching the OpenAI/Google shape. Any consumer that reads `fullStream` for
  reasoning events (e.g. F8 `report-workspace-assistant.ts`'s `reasoning-delta`
  branch) works as-is once the consumer's resolver outputs the right
  `providerOptions.anthropic.thinking`.
- One follow-up for the formal provider Feature: derive
  `outputTokenDetails.reasoningTokens` in the Anthropic session wrapper so
  analytics don't silently zero out (P1, no Spike blocker).
